# VGamepadWeb

[English](README.md) | 简体中文

把手机变成 PC 的无线手柄：PC 上跑一个服务端，同一局域网里的手机打开网页就能玩，不用装 App，也不用额外的接收器。

输入走 WebRTC 数据通道，信令走 SignalR；PC 端把输入翻译成 Windows 认得的虚拟手柄信号。游戏看到的是「一支真的插在电脑上的手柄」，所以支持手柄的游戏都不用改。

![服务端界面](README/%E6%9C%8D%E5%8A%A1%E7%AB%AF%E4%B8%AD%E6%96%87%E7%95%8C%E9%9D%A2.jpg)

## 它是怎么工作的

服务端启动后监听一个端口，把内置的网页一起发出去。手机浏览器打开这个地址，选好手柄类型、连上，屏幕上出现手柄：摇杆、按键、十字键、扳机。按下时输入经由 WebRTC 数据通道送到 PC，PC 端写进 ViGEmBus 创建的虚拟手柄，系统和其他游戏就当作普通 XInput / DualShock 设备来用。

---

## 槽位、保留与重连

这是这个项目最核心的机制，值得单独说清楚。

服务端固定提供 **4 个槽位**，对应 Windows 的 XInput 0–3，界面上叫「手柄 1 ~ 手柄 4」。一个槽位同一时刻只服务一台手机。

### 设备常驻

槽位上的虚拟手柄**不是连接时创建、断开时销毁**的。它只在第一次被认领时创建一次，之后一直挂在系统里：

- 手机断开 → 服务端只收回「占用权」，设备本身不拔；
- 手机重连 → 拿回同一个槽位，用的还是同一台设备、同一个 XInput 编号；
- 设备只有在「卸载」或者程序退出时才真正销毁。

这样做的目的很实际：游戏是按 XInput 编号认玩家的。如果每次断开都把设备拔掉，第二个连进来的人会顶到 1 号位，游戏里就变成「玩家 2 突然变成了玩家 1」。设备常驻之后，谁坐过哪个位子就一直是那个位子。

### 记住「上次是谁坐的」

每个槽位会记住上一位占用者：

- **设备码**优先——手机端第一次打开页面时在 localStorage 里生成的持久 UUID；
- **远程 IP** 兜底——给没带设备码的老页面用。

这份记忆**只存在于本次服务端进程内**，服务重启就清空。它只用来决定「该给谁留哪个位子」，不参与鉴权。

### 手机会分到哪个槽

手机连上来时并不指定槽位（现在的客户端不选槽），由服务端按下面的顺序决定：

1. **认回自己上次的槽**——空闲、且设备码（或 IP）和这台手机对得上；
2. **从没用过的干净槽**——优先把「新人」放进没人坐过的位子，而不是去捡别人留下的；
3. **最小的空闲槽**——四个位子都被用过时，按编号从小到大给；
4. 四个都占着 → 手机收到「没有空闲槽位了」，停在连接门，不会硬挤。

### 重连

同一台手机重新连上，会走「认回自己上次的槽」这条路，于是：

- 槽位编号不变；
- 虚拟手柄不重建、不重新插拔；
- 游戏里仍然是同一个玩家号。

### 换手柄类型

连接门里选的手柄类型决定服务端建哪种设备。如果某台手机上次用的是 Xbox 360，这次改选 DualShock 4 再接进来，服务端会在**同一个槽位上先拔掉旧设备、再建新的**：

- 先拆后建，是因为同时存在的虚拟设备数量有限（4 个槽位就是 4 台），旧设备还占着就建新的会凑出第 5 台；
- 建在原来的槽位，所以玩家号不变，只是「手柄换了型号」。

### 卸载设备

槽位空闲但设备还挂着的时候，服务端卡片上会出现「卸载」：

- 它把这座虚拟手柄从系统里拔掉并释放（设备管理器里随之消失）；
- 「上次是谁坐的」这份记忆**保留**——同一台手机再连进来，还是回到这个槽号，设备按类型重新建。

### 槽位什么时候释放

占用权在三种情况下会被收回：

| 情况 | 触发者 |
| --- | --- |
| 关闭 / 离开页面 | 手机端尽力调用一次 Release，服务端立即释放 |
| 网络断开、App 被系统挂起 | SignalR 心跳超时（约 30 秒）后服务端清理 |
| 管理员在服务端点「断开连接」 | 服务端主动踢出，手机会收到「你已被管理员踢出」 |

释放之后，卡片上的状态从「已连接」变成「等待设备重连」（挂着的设备还在）或「等待设备接入」（槽位从没建过设备，或设备已被卸载）。

## 服务端

Windows 桌面程序，一个自绘的控制台界面：整块画面按 980×580 的设计稿排版，等比缩放居中，窗口可以自由拉伸。

### 界面

![服务端英文界面](README/%E6%9C%8D%E5%8A%A1%E7%AB%AF%E8%8B%B1%E6%96%87%E9%A1%B5%E9%9D%A2.jpg)

- **手机访问地址**：显示当前局域网地址，旁边是复制按钮和二维码，手机扫码直接打开；
- **服务器端口 / 访问密码**：服务运行时只读，停止后才可编辑；密码留空表示不设密码；
- **启动 / 停止**：一个按钮搞定，状态用颜色和文字同时表达；
- **配置**：界面语言（中文 / English / العربية，阿语整体 RTL 镜像）与二维码；
- **页脚**：版本号与深浅色开关。

主题默认跟随 Windows 的深浅色设置，也可以在页脚手动切换，选择会记进配置文件。

### 槽位卡

四张卡片，一槽一张：编号、标题（手柄 N）、状态徽标、设备类型（Xbox 360 / DualShock 4），已连接的卡还会显示手机自报的机型与局域网 IP。

- 已连接：显示「断开连接」；
- 空闲但设备还挂着：显示「等待设备重连」、设备类型，以及「卸载」；
- 从来没建过设备：显示「等待设备接入」。

### 启动自检

点「启动服务」之后，服务端不只看自己的状态机，而是真的去连一次本机端口、再取一次首页：

- 端口没在监听 → 启动失败，明确报出来并把服务收干净；
- 首页打不开、或返回的不是预期页面 → 同样报错，而不是显示「运行中」却怎么都打不开。

### 托盘与单实例

- 点窗口的 × 是收进通知区域，服务继续跑；托盘图标右键才有「退出」；
- 退出时先停服再关进程，不会留下半个占用中的端口；
- 同一时间只允许一个实例，重复双击会提示「已经在运行」，不会出现两个托盘图标抢同一个端口。

### 配置与日志

| 内容 | 路径 |
| --- | --- |
| 设置（端口 / 密码 / 语言 / 主题） | `%APPDATA%\VGamepadWeb\settings.json` |
| 运行日志 | `%APPDATA%\VGamepadWeb\server.log` |

配置文件损坏时不会静默重置，会在日志里留一条记录，然后按默认值启动。

## 手机端

### 连接门

![手机端连接界面](README/%E5%AE%A2%E6%88%B7%E7%AB%AF%E7%99%BB%E5%BD%95%E7%95%8C%E9%9D%A2.jpg)

没连上之前，整页被一块覆盖层盖住，手柄是点不到的。门里只有连上才需要决定的东西：

- **密码**：服务端没设密码就留空；
- **手柄类型**：Xbox 360（Xbox）/ Xbox 360（Nintendo Switch）/ DualShock 4（PlayStation）——前两个建的是 Xbox 360 虚拟设备，只是按键画法不同；第三个建的是 DualShock 4。连上之后就锁定了，换类型要断开重连（服务端会在原槽位拆旧建新）；
- **连接**；
- **全屏**：进入全屏时会顺带尝试锁定横屏（支持方向锁的浏览器会直接转过来，不支持的只能靠提示）；
- **语言**：中文 / English / العربية；
- 标题下一句「建议横屏使用」——手柄界面横着用更顺手。

连上之后覆盖层消失，剩下手柄本身和顶栏。

### 顶栏

连接状态（圆点 + 文字）、延迟、玩家号 `P1`，然后是配置方案、振动开关、灵敏度（10%–200%）、全屏、编辑、菜单。

- **配置方案**：每套方案独立保存按键位置、显示隐藏等布局，按「方案 + 按键风格」分开存；
- **振动**：手机会收到服务端转来的振动强度，用手机的振动马达反馈；
- **灵敏度**：直接作用在摇杆轴值上，100% 是原始值；
- **编辑**：进入编辑模式后可以拖动控件、打开触控热区显示、逐个显示/隐藏按键；
- **菜单**：重置布局、导出、导入、新建方案、删除方案、关于。

### 触摸行为

为了让它像手柄而不是网页：

- 禁掉右键菜单、长按选择、拖拽幽灵、页面刷新等会打断操作的浏览器行为；
- 锁屏、切换 App、窗口失焦时，会把所有按住的键补一次「松开」、摇杆归中——否则回来时游戏里还踩着油门；
- 摇杆和按键都接住了 `touchcancel`，系统打断手势不会让输入卡死。

## 项目结构

### VGamepadWeb.UI

手机端网页，也是整个项目的界面层。

**React 19 + Vite 8 + TypeScript**，与服务器之间的信令走 **SignalR**（`@microsoft/signalr`），图标用 **Lucide React**。

构建产物直接写进 `VGamepadWeb.WinForm/wwwroot`，由桌面程序一起发出去，不需要单独跑前端服务。

### VGamepadWeb.Core

服务端核心库。

**.NET 10 + ASP.NET Core**：HTTP 服务、SignalR Hub、WebRTC 信令、会话与槽位管理，以及把输入翻译成虚拟手柄事件。

- 虚拟手柄：**ViGEmBus** + [Nefarius.ViGEm.Client](https://github.com/nefarius/ViGEmClient)，Windows 看到的是真的 Xbox 360 / DualShock 4 设备；
- WebRTC：[SIPSorcery](https://github.com/sipsorcery-org/sipsorcery)，负责 PeerConnection、ICE 协商与数据通道。

> ⚠️ 宿主机必须装 **ViGEmBus** 驱动，虚拟手柄才存在。程序首次启动会自动静默安装内置的安装包；装失败会提示并退出。

### VGamepadWeb.WinForm

桌面端，**.NET 10 Windows Forms**，包住 Core：启停服务、看槽位、改设置、托盘常驻，并把 `wwwroot` 里的网页一起发出去。

### VGamepadWeb.Console *(仅供开发)*

早期用来在终端里跑 Core 的入口，日常使用请用 WinForm。

## 从源码构建

```powershell
# 1) 前端：构建产物会直接写进 VGamepadWeb.WinForm\wwwroot
cd VGamepadWeb.UI
npm install
npm run build

# 2) 服务端
cd ..
dotnet build VGamepadWeb.slnx

# 3) 运行
dotnet run --project VGamepadWeb.WinForm
```

> 改了前端源码之后必须重新 `npm run build`，否则发出去的还是旧页面。

## 运行要求

- Windows 10 或更高版本
- [.NET 10](https://dotnet.microsoft.com/download/dotnet/10.0)（构建需要 SDK，仅运行需要运行时）
- [ViGEmBus 驱动](https://github.com/nefarius/ViGEmBus/releases)（v2.0.0 之后会随程序自动安装）
- 手机与 PC 在同一个 Wi-Fi / 局域网
- 构建前端需要 Node.js 20 或更高版本

> 页面通过 **HTTP** 在局域网内提供，不需要证书。这也意味着浏览器的一些「安全上下文」能力（例如 Wake Lock）不可用，长时间游戏时建议把手机的自动息屏时间调长。
